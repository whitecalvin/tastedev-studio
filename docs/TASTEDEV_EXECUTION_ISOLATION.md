## Contract

An optional `executionIsolation:1` capability/requirement and a versioned step policy identify enforced execution. The first policy is workspace-only filesystem access, network denial and child-process denial. It is part of the reviewed payload/Source identity. A missing capability, missing policy, unknown version or unsupported backend fails closed. Source transfer, HTTP checks and owned-service cleanup are trusted Agent broker operations; executable project steps require the policy. The normal legacy path must never be labelled isolated.

## Windows implementation target

Use AppContainer for untrusted executable project code, not a writable-directory convention. The trusted Agent/Core/SDK broker retains control/evidence communication outside the untrusted process. Original Claude SDK tools remain bounded by the existing verified bundle, path/tool policy and per-proposal approval; do not claim that merely wrapping a broker sandboxes code it launches later. Godot must use the same strict leaf launcher at its actual process creation.

Create a unique temporary per-run AppContainer profile. Copy the saved Source and explicitly configured SHA-verified runtime executable into that owned profile. Grant access only to these copies; never change ACLs on the original project, installed runtime or credential directories. Pass a scrubbed environment and no network capabilities. Use the Agent's suspended-start Job ownership with an active-process limit of one, no breakaway, UI restrictions and kill-on-close cleanup. Leaf timeout/cancellation is typed and observed at bounded intervals. Tools needing child processes or unavailable runtime dependencies must report the limitation rather than run on the host silently.

The mirrored Source keeps relative paths and recorded content hashes. Check Source integrity after execution; transfer only explicitly declared artifacts through the trusted broker, with path/reparse/hash/size checks. Runtime caches and user credentials are not copied. Parent Agent owns profile cleanup, including cancellation and timeout. Journal only the unique owned identity for crash recovery; never delete another application profile.

Local executable configuration must be outside untrusted Source, absolute, bounded and SHA-verified. A project cannot change the allowlist or choose arbitrary shell execution. Exact supported programs, output policy, recovery and actual test evidence are still being implemented.

## Other OS and Native UI

#### Explicit dependency manifest contract

Each program may optionally define `files`, an array with these fields:

| Field | Required value |
| --- | --- |
| source | Absolute local file outside the Agent project workspace; no reparse or credential filename |
| path | Safe relative destination inside the private program directory |
| size | Exact byte count, including zero-byte runtime modules |
| checksum | Lowercase64-character SHA256 of that file |

The program image checksum remains separate. The dependency binding includes destination names, sizes, hashes and the preserved native executable filename; host source paths are excluded. Changing a dependency or destination changes this binding. No environment, credential directory, dependency cache or containing host folder is implicitly copied. File/directory locks remain owned by LockedProgram until the leaf exits. Copy/preparation failure leaves exact profile ownership for safe cleanup/recovery; it never overwrites original Source or a runtime installation.
