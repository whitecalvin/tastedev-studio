# 역할 기반 팀 오케스트레이션

2026-10-24. 작업 저장소: sources/v1.0/tastedev-studio. 기능 구현과 설치 패키지/배포 검증은 구분한다.

## 용어와 구성

장비는 실행 환경, Agent는 그 장비의 실행 프로세스, 실행 역할(구현/배포/테스트)은 자원 배정 축이다. 새로운 팀 책임(리더/설계/구현/독립 검토/문서화)은 담당 업무를 나타내며 AI 프로필은 공급자·모델·연결·도구·요청 예산을 나타낸다. 하나를 다른 하나로 추측하지 않는다. Core 위치의 AI 모델 호출과 장비 Agent의 테스트 실행은 서로 다르다.

새 프로젝트의 ‘팀 구성’에서 역할 팀 초안을 선택하거나 기존 오케스트레이션의 ‘프로젝트 팀’에서 초안을 추가한다. 기존 장비·역할·관계·AI 프로필과 좌표를 보존하고 새 카드에 비어 있는 위치를 배정하며 실제 Agent나 Provider 연결을 만들어 냈다고 표시하지 않는다. 프로필과 그래프를 각각 저장한 뒤 저장된 Protocol과 비밀 제외 Snapshot으로 Core에 게시한다. 기존 프로젝트는 기본 구성이 바뀌지 않는다.

## 작업 의도와 결정

‘팀 운영 → 작업 의도’에 원래 요청, 목표, 제외 범위, 완료 조건, 허용 상대 경로, 담당 책임을 입력한다. Core는 마스킹된 원문과 SHA-256 digest, 판, 변경 사유, 과거 판, 결정 이력을 보존한다. 변경은 새 판이며 준비 승인을 해제한다. 같은 프로젝트의 실행/검토/중지 대기 작업이 남아 있으면 작업 의도 수정은 거부한다. 새 작업 의도 판은 새 계약과 승인을 필요로 한다.

## 배정과 계획

게시된 역할 → 작업 및 장비 → Agent → 역할 관계를 검증하고 Agent 접근 권한, 정확한 AI 프로필, 그래프 판/input checksum을 배정에 고정한다. 연결되지 않은 Agent와 오래된 그래프의 배정을 실행 가능한 것으로 추측하지 않는다. 화면은 미배정, Agent 부재/사용 중, 변경된 그래프, Factory 의존성/자원 대기 사유를 표시한다.

리더의 분석 프로필이 있으면 기존 Factory 계획 기능에서 사용한다. 모델의 분할 결과는 실제 읽은 소스, 허용 경로, 완료 조건의 부분집합, 선행 의존성을 기존 parser로 검증한다. 저장은 초안 생성이며 Queue 승인은 별도다. 구현 작업은 준비된 의도를 기존 Factory 계약에 연결한다. 설계/리더/문서/검토 단독 실행은 기존 Graph AI 승인 화면을 사용하며 원래 요청·규칙·관련 인계/결정 문맥을 보여 준다.

## 권한

Core의 taskAIRequest와 게시 검증에서 구현 책임만 verified-fix 정책을 허용한다. 다른 책임은 analysis 전용이며 검토 프로필은 review 역할이어야 한다. 읽기 전용 책임 실행에 구현/배포 후속 관계가 있으면 거부한다. 의도 연결 계약의 경로·완료 조건·배정은 Core에서 재검증한다. 의도 연결 계약의 최종 검토 노드는 반드시 독립 검토 책임에 속해야 한다. 실패 재시도도 현재 작업 의도·권한을 다시 확인하고 성공한 노드를 유지한다. 기존 AIService의 read tools, FixService의 제안별 파일/hash 승인, Dirty/충돌 보호, Protocol 검증 및 실제 Agent 재시험을 재사용한다. 임의 shell, 자동 commit/push, 무승인 patch 또는 배포 권한을 추가하지 않는다.

## 품질 관문과 독립 검토

테스트·정적 검사·화면·문서·결과 보고 각각의 근거를 기록한다. 자동 Run, 수동 검토, 유효한 근거 재사용, 실패, 미실행, 해당 없음을 구분한다. 테스트 통과/재사용은 Core의 실제 PASS Run과 현재 실행 또는 FixAttempt retest, Snapshot manifest checksum이 일치해야 한다. 다른 관문의 수동 결과는 검토자·근거/적용 제외 사유를 남긴다. 자동 검사라고 표시하지 않는다.

같은 작업/의도 판/현재 시도/실제 수정 후 Snapshot에 맞는 최신 근거만 최종 수락에 사용한다. 필수 테스트에 ‘해당 없음’을 허용하지 않는다. 하나라도 실패/미실행/누락이면 Factory 수락은 차단되며 기존 독립 모델 검토·정확한 소스 읽기·실제 시험 요구도 그대로 적용된다. 변경 요청/취소는 근거 부족 때문에 차단하지 않는다.

## 인계와 복구

프로젝트 수신함은 Core의 암호화 저장소 단위를 사용한다. 요청/질문/인계/검토와 받는 책임, 수신 확인자를 보존한다. 외부 메일·다른 Codex 세션 전송 또는 자동 실행은 없다. 수신 확인은 사용자 조작 기록이며 Agent가 읽었다는 증거로 해석하지 않는다. 역할 실행의 승인된 프롬프트에 관련 인계의 제한된 발췌를 포함한다.

변경 요청에는 workspace revision과 requestId가 있다. 이미 커밋된 동일 요청의 응답 유실 재시도는 중복 생성 없이 현재 상태를 돌려준다. 다른 내용/사용자/프로젝트로 같은 identity를 재사용할 수 없다. 권한은 재시도에서도 다시 검사한다. 저장 실패 시 이전 메모리 상태를 유지하며 손상된 저장소를 지우고 초기화하지 않는다. Core 재시작의 Graph/Factory pause 및 기존 작업 재개 확인을 재사용한다.

## 프로젝트 지식

피드백에서 규칙 초안을 만들고 적용 범위를 프로젝트/책임으로 선택한다. 명시적 사용자 승인 후에만 새 준비 작업에 규칙을 고정한다. 진행 중인 계약의 규칙을 조용히 바꾸지 않는다. 새 규칙 적용은 의도를 새 판으로 수정하고 준비 승인한다. 폐기한 규칙과 근거 메시지 이력은 보존한다. Codex 개인 메모리는 변경하지 않는다.

## GUI와 운영

오케스트레이션 관계 화면 안에 프로젝트 팀과 팀 운영(작업 의도/배정/품질/수신함/규칙)을 배치한다. 배정된 노드, 실제 Graph/Factory 상태, 현재 시도의 Source를 연결한다. 새로운 테스트 실행기·Scheduler·배포 파이프라인을 만들지 않는다. 다국어 문구와 공통 32px 입력/선택/단추, 키보드 탭 탐색을 사용한다.

## 제한과 검증 경계

- Core를 메모리 모드로 띄우면 재시작 영속성이 없음을 표시한다. 영속 운영은 기존 암호화 SQLite 설정을 사용한다.
- 프로젝트당 의도 100개, 이력 20판/의도, 메시지·근거 각 500개, 규칙 100개, 요청 영수증 1000개, 총 JSON 2MB로 제한한다. 용량을 넘으면 보존하며 추가를 거부한다. 자동 이력 삭제는 없다.
- 업무 의미의 자동 배정/무인 승인은 하지 않는다. 장비 Agent와 AI 프로필은 실제 연결 설정이 필요하다.
- 설치본·패키지·Linux·사용자 운영 배포는 이번 작업의 검증 대상이 아니다.
- 실제 Provider 최종 검증은 사용자 재로그인 후 완료했다. 실제 모델 분석 7건과 수정 작업 2건, 실제 Rust Agent의 최초 FAIL → 개별 재시험 PASS → 최종 통합 PASS, 설계/문서 역할의 Source 변경 0을 확인했다. 개별 diff의 사람 수동 검토와 설치본 QA를 대신한 것으로 주장하지 않는다.
- 만료된 ChatGPT 계정 조회가 실패해도 `npm run ai:login`이 공식 로그인 흐름을 다시 시작한다. 계정/모델 RPC 오류의 401을 인증 오류로 구분하며 원본 인증 진단은 노출하지 않는다. 공식 계약: [Codex App Server 인증](https://learn.chatgpt.com/docs/app-server#authentication-modes).
- 변경 범위와 실제 검사 결과는 resources/verification/dev-01/role-team-orchestration-20261024/checkpoint.json 및 RESULT.ko.md를 참조한다.
