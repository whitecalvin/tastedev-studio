# 빌드·패키지 하위 노드 그룹

사용자가 확정한 구조는 **빌드·패키지 부모 노드 안에 단계별 하위 노드를 묶는 구조**다. 공용 릴리스 스크립트를 복사하거나 전체 명령을 실행하는 단일 래퍼 노드로 만들지 않는다.

```text
빌드·패키지
 ├─ 소스 준비 → 의존성 준비 → 빌드 → 테스트
 └─ 파일 구성 → 서명 → 패키징 → 패키지 검증
```

위 표시의 하위 실행 순서는 소스 준비부터 패키지 검증까지 이어지는 하나의 순차 흐름이다. 화면에서는 4열·2행으로 배치한다.

## 사용 순서

1. 오케스트레이션 화면의 **노드 추가 → 빌드·패키지**를 선택한다. 부모 1개와 하위 작업 8개가 생성된다. 기존 60개 제한에 모두 포함한다.
2. 역할 노드에서 부모로 `performs` 관계를 연결하면 하위 작업이 그 역할의 장비·Agent 배정을 사용한다. 특정 하위 작업에 역할을 직접 연결하면 해당 작업의 명시적 역할을 사용한다.
3. 부모를 선택하면 설정 패널에서 하위 단계로 이동할 수 있다. 각 단계에서 Protocol 작업 또는 테스트를 선택한다. 참조가 없는 단계는 실행 준비가 되지 않으며 Core 게시에서 거부한다.
4. 외부 성공·실패 흐름은 하위 작업에 직접 연결하지 않고 부모에 연결한다. 입력은 첫 하위 노드, 성공 출력은 마지막 하위 노드로 연결된다. 외부 승인을 건너뛰고 첫 하위 작업부터 시작할 수 없다.
5. 실행 검토·승인 후 기존 Core/Queue/Agent Pipeline에서 하위 작업이 각각 실행된다. 부모는 하위 결과를 집계하며 별도의 가짜 Run을 만들지 않는다.

## 그룹 조작

- 부모의 핸들을 드래그하거나 방향키로 이동하면 하위 노드도 같은 거리만큼 이동한다.
- 접기·펼치기는 부모 우측 아이콘과 컨텍스트 메뉴에서 조작한다. 표시 상태는 프로젝트별 별도 저장소에 저장해 Graph 정의·체크섬·실행 승인을 바꾸지 않는다.
- 접힌 그룹의 하위 노드를 검색하거나 설정 목록에서 선택하면 그룹을 펼친다.
- 그룹 복제는 하위 정의와 내부 연결을 복제하되 외부 연결과 실행 참조는 복제하지 않는다.
- 부모 삭제는 하위 노드와 관련 관계도 함께 제거한다. 파일·Agent·실제 작업을 삭제하지 않는다.
- 흐름 정렬은 그룹의 하위 상대 위치를 유지한다. 그룹의 겹침 순서와 드래그 중 최상단 표시는 하위 노드에도 적용한다.

## 실행·복구

부모의 외부 실패 경로는 실패한 하위 단계에서 연결한다. 해당 하위 단계에 명시적인 실패 경로가 있으면 이를 우선한다. 완료된 하위 작업, 실패한 작업, 다음 작업의 대기 intent는 기존 Core의 영속화·재개 경로를 사용한다. 승인·배포 보호와 장비 실행 정책도 그대로 적용한다.

현재 그룹은 한 단계 깊이만 지원한다. 자식으로 작업·승인 노드를 저장할 수 있으며 그룹 안에 다시 그룹을 넣는 중첩 구조는 허용하지 않는다. 새 노드 종류를 사용하는 Studio와 Core는 함께 갱신해야 한다. 기존 평면 프로젝트 데이터는 계속 읽는다.

## 확인한 범위

2026-11-06 기준 전체 Node1265 PASS, lint/typecheck와 production Web export를 확인했다. 실제 Web 밝게·어둡게에서 접기, 새로고침 후 표시 복원, 하위 노드 포함 관계, 부모 요약 비겹침, 아이콘 치수, 화면 넘침 없음을 확인했다.

기존 실제 Rust Agent에서 합성 Node 작업8개를 실행해 하위별 Job/Run8개 PASS와 부모 집계를 확인했다. 이것은 그룹 실행 연결 검증이다. 단계의 이름이 빌드·서명·패키징이라는 이유로 해당 도구의 실제 작업까지 완료했다고 기록하지 않는다. 실제 제품 빌드·서명·패키징·게시 기능 전체를 스크립트와 동등하게 이식했다는 판정도 하지 않는다.

현재 제공하는 것은 부모·하위 그룹과 기존 Protocol 작업을 연결하는 실행 구조다. 기존 공용 도구는 수정하지 않았다. 제품 패키징·설치·운영 게시·버전 변경·커밋/푸시는 수행하지 않았으며 103에 접근하지 않았다.
